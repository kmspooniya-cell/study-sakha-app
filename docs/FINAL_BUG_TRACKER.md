## Fixed Defects (This Audit)

| ID | Severity | Subsystem | Root Cause | Fix & Files Changed | Verification |

| **BUG-028** | **P0** | AlarmEngine / Android Manifest | `app.json` set `expo-image-picker` `"cameraPermission": false`, injecting `<uses-permission android:name="android.permission.CAMERA" tools:node="remove"/>` into `AndroidManifest.xml`, which stripped `CAMERA` permission during manifest merge. Additionally, `<queries>` lacked `android.media.action.IMAGE_CAPTURE`, causing `resolveActivity()` in `AlarmMissionEngine.kt` to return `null` on Android 11+. | Updated `app.json` `expo-image-picker` `cameraPermission` to a user-facing rationale string, moved `./plugins/withAlarmEngine` to run after `expo-image-picker`, and updated `plugins/withAlarmEngine.js` (`addPermission` strips `tools:node="remove"` and `addQueryIntent` adds `android.media.action.IMAGE_CAPTURE`). | **Host Verified:** `expo prebuild --no-install --platform android` generated `AndroidManifest.xml` with `<uses-permission android:name="android.permission.CAMERA"/>` (no `tools:node="remove"`) and `<action android:name="android.media.action.IMAGE_CAPTURE"/>`. Device runtime **Not Verified**. |
| **BUG-029** | **P0** | AlarmEngine Scheduler | `AlarmEngineScheduler.sync()` called `cancelSnapshot()` -> `cancelAlarm()`, which cancelled both `ACTION_FIRE` and `ACTION_SNOOZE`. Because `handleSnoozeAlarm` in `StudySakhaAlarmModule.tsx` updates `alarms` (`snoozeCount`), the `syncNativeAlarms` `useEffect` immediately wiped out the newly scheduled `ACTION_SNOOZE`. `rescheduleStored()` also cancelled pending snoozes of other alarms. | Added `cancelFire(context, alarmId)` in `native/alarm/android/java/com/anonymous/agonpreview/AlarmEngineScheduler.kt`. `rescheduleStored()` now cancels only `ACTION_FIRE`. `sync()` cancels only `ACTION_FIRE` for alarms remaining active/enabled and calls `cancelAlarm()` only for removed/disabled/skipped alarms. | **Host Verified:** Source audit + `expo prebuild` + `test/heavySleeperMissions.test.tsx`. Kotlin compile & device snooze **Not Verified**. |
| **BUG-030** | **P1** | AlarmPlaybackService | `buildNotification()` omitted `EXTRA_HEAVY_SLEEPER` and `EXTRA_MISSION_BEFORE_SNOOZE` from `ACTION_SNOOZE_NOTIFICATION`, dropping Heavy Sleeper protection when snoozed from the notification. Multi-alarm `stopAlarm()` rebuilt the remaining alarm's notification with hardcoded `heavySleeper = false` and default snooze metadata. Duplicate `ACTION_FIRE` restarted active playback/volume ramp, and `if (players.isEmpty())` missed tracking foreground state if `MediaPlayer.create` returned `null`. | Added `ActiveAlarmMeta` map and `isForeground` tracking in `native/alarm/android/java/com/anonymous/agonpreview/AlarmPlaybackService.kt`, forwarded `EXTRA_HEAVY_SLEEPER` and `EXTRA_MISSION_BEFORE_SNOOZE` on `snoozeIntent`, made `onStartCommand` idempotent for already-ringing alarms, cancelled prior `volumeRamps` before ramping, and used `activeMeta[remainingId]` in `stopAlarm()`. | **Host Verified:** `test/heavySleeperMissions.test.tsx` + `expo prebuild`. Kotlin compile & device multi-alarm **Not Verified**. |
| **BUG-031** | **P2** | AlarmEngineModule | `scheduleSnooze()` called `config.getInt("volume")` and `config.getBoolean("vibration")` without `hasKey` guards, risking `NoSuchKeyException`. | Added `config.hasKey(...)` defaults (`100`, `true`) in `native/alarm/android/java/com/anonymous/agonpreview/AlarmEngineModule.kt`. | **Host Verified:** Source audit + `expo prebuild`. |
| **BUG-032** | **P2** | FocusLockBlockingActivity | `LinearLayout.LayoutParams(-1, 56)` used raw `56px` (~14–18dp on xxhdpi/xxxhdpi screens) for the "Return to Study" button. | Converted to `(56 * resources.displayMetrics.density).toInt().coerceAtLeast(56)` in `native/focus-lock/android/java/com/anonymous/agonpreview/FocusLockBlockingActivity.kt`. | **Host Verified:** `expo prebuild` + `test/stabilityFailureScenarios.test.tsx` template sync check. |
